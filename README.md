# InfiniteDesk

Бесконечный холст-«рабочий стол» для Windows 11 в духе Wayland-композитора
[driftwm](https://github.com/malbiruk/driftwm): окна живут на бесконечном
2D-полотне, экран — камера над ним. Полотно панорамируется и зумится, окна
примагничиваются друг к другу в кластеры, камера умеет «обзор всех окон»,
«домой», центрирование и закладки позиций.

Один самодостаточный `InfiniteDesk.exe` — скачал, запустил, пользуешься.
Выход — через значок в трее или `Ctrl+Alt+Q`.

## Что это (и что это не так)

driftwm — Wayland-композитор: он сам владеет отрисовкой всех окон, поэтому
может попиксельно зумить их живое содержимое. В Windows 11 композитор — DWM,
он обязательный и закрытый: его нельзя заменить, и нельзя перехватить рендер
чужих окон. Поэтому InfiniteDesk — **гибрид**, ближайшее реально возможное
приближение:

* **Слой-холст.** Собственное полноэкранное окно на DirectComposition/Direct2D
  строго **за** всеми пользовательскими окнами: обои + бесконечная точечная
  сетка, которые панорамируются и зумятся вместе с камерой. Именно этот слой
  создаёт ощущение отдельного пространства.
* **Вблизи — настоящие окна.** Реальные top-level окна раскладываются по
  холсту геометрически: камера двигает и масштабирует их через
  `SetWindowPos` (батчем `DeferWindowPos`). Это живые интерактивные окна.
* **Вдали — живые превью (стретч-фича).** При сильном отдалении реальные окна
  паркуются за экран, а на холсте рисуются их живые изображения через
  Windows.Graphics.Capture — «отдалиться и увидеть всё сразу». Клик по превью
  — перелёт камеры к окну и возврат реальных окон. Если WGC недоступен,
  остаётся чисто геометрический зум (приложение честно деградирует, а не
  ломается).

### Честные ограничения

* Это **не композитор**. DWM остаётся владельцем экрана; попиксельного зума
  живого содержимого окна в «ближнем» режиме нет — окна масштабируются
  геометрически (меняется их реальный размер).
* Геометрический зум упирается в минимальные размеры окон
  (`WM_GETMINMAXINFO`): ужать окно ниже его минимума нельзя, оно клампится
  и визуально становится «крупнее», чем следовало бы. Дальний режим (превью)
  этого ограничения не имеет.
* 240 FPS — частота **нашего** цикла: подложки, ввода и обработки камеры.
  Перерисовка чужих окон ограничена DWM и стоимостью их перемещения, поэтому
  сами окна могут визуально обновляться реже. Это ожидаемо.
* Развёрнутые (maximized) и полноэкранные окна исключены из зума/перемещения.
* Окна `WS_EX_TOPMOST` (OSD, закреплённые утилиты) не управляются.
* Оболочка не заменяется: Explorer, панель задач (`Shell_TrayWnd`), обои и
  иконки рабочего стола продолжают работать. Панель задач никогда не
  двигается и не зумится. Иконки рабочего стола визуально перекрыты
  слоем-холстом (сам холст рисует ваши обои).
* `Ctrl+Alt+Del` перехватить нельзя — это забота Windows, так и должно быть.

## Требования

* Windows 11 x64 (использованы per-monitor DPI v2, DirectComposition, WGC).
* Для управления окнами программ, запущенных **от администратора**
  (например, Диспетчер задач), InfiniteDesk тоже должен быть запущен от
  администратора — иначе такие окна просто не двигаются (UIPI).

## Управление

Базовая схема — `Ctrl+Alt` (+ мышь), в духе driftwm:

| Действие | Управление |
|---|---|
| Зум к курсору | `Ctrl+Alt` + колесо мыши |
| Панорамирование | `Ctrl+Alt` + зажатая средняя кнопка + движение |
| Панорамирование (по пустому холсту) | перетаскивание ЛКМ/СКМ по холсту, колесо — зум |
| Инерция | отпустить кнопку в движении — полотно катится и тормозит |
| Двигать окно (со снаппингом) | `Alt` + ЛКМ-драг по окну |
| Двигать кластер целиком | `Alt+Shift` + ЛКМ-драг |
| Ресайз окна | `Alt` + ПКМ-драг |
| Ресайз кластера целиком | `Alt+Shift` + ПКМ-драг |
| Обзор всех окон (zoom-to-fit, туда-обратно) | `Ctrl+Alt+W` |
| «Домой» (в начало и обратно) | `Ctrl+Alt+Home` |
| Центрировать активное окно | `Ctrl+Alt+C` |
| Сброс зума в 1.0 | `Ctrl+Alt+0` |
| Перейти к закладке камеры 1–4 | `Ctrl+Alt+1..4` |
| Сохранить закладку 1–4 | `Ctrl+Alt+Shift+1..4` |
| FPS-оверлей | `Ctrl+Alt+F` |
| Выход | `Ctrl+Alt+Q` или трей → Выход |

Пока зажаты `Ctrl+Alt`, колесо и средняя кнопка **глобально поглощаются**
низкоуровневым хуком (`WH_MOUSE_LL`) и не доходят до приложения под курсором —
так задумано: управление камерой работает поверх любых программ и их
шорткатов. `Alt`+ЛКМ/ПКМ-драг над окнами тоже перехватывается глобально.

Все биндинги переназначаются в `config.ini` (секция `[Hotkeys]`).

## Конфиг

`config.ini` лежит рядом с exe и создаётся автоматически. Ключевое:

* `[Camera]` — `MinScale`/`MaxScale` (пределы зума), `ZoomStep` (шаг колеса),
  `FlyDurationMs` (длительность перелётов камеры).
* `[Input]` — `InertiaFriction` (трение инерции), `InertiaMinSpeed`
  (минимальная скорость флика).
* `[Snap]` — `Enabled`, `SnapDistance` (дистанция примагничивания, экранные px),
  `ReleaseFactor` (гистерезис отлипания), `Gap` (зазор между окнами).
* `[Render]` — `TargetFPS` (цель цикла, по умолчанию 240), `GridStep`,
  `BackgroundColor`/`GridDotColor` (AARRGGBB), `DrawWallpaper`.
* `[Preview]` — `Enabled`, `BelowScale` (порог входа в режим превью),
  `AboveScale` (порог выхода, гистерезис).
* `[Debug]` — `ShowFps`.
* `[Bookmarks]` — заполняется автоматически при сохранении закладок.

## Сборка

**Visual Studio 2022:** открыть `InfiniteDesk.sln`, конфигурация
Release | x64, собрать. Нужен workload «Разработка классических приложений
на C++» (MSVC v143 + Windows 11 SDK). Всё статически (`/MT`), внешних
зависимостей и NuGet-пакетов нет — C++/WinRT берётся из Windows SDK.

**Командная строка:** `build.cmd` (найдёт MSBuild через vswhere) или

```
msbuild InfiniteDesk.sln /m /p:Configuration=Release /p:Platform=x64
```

Результат: `build\x64\Release\InfiniteDesk.exe`.

**GitHub Actions:** на каждый пуш собирается Release x64, готовый exe
выкладывается артефактом `InfiniteDesk-x64` (вкладка Actions → последний
запуск → Artifacts) — можно просто скачать, не собирая руками.

## Архитектура (кратко)

* `Camera.h` — камера `offset`+`scale`, единственные хелперы
  `VirtualToScreen`/`ScreenToVirtual`, анимация перелётов и инерция.
* `CanvasWindow` — слой-холст: DComp+D2D, обои, бесконечная сетка (один
  `FillRectangle` с wrap-брашем — сетка бесплатна на любом зуме), отрисовка
  превью; всегда прижат к низу Z-порядка (`WM_WINDOWPOSCHANGING`).
* `WindowTracker` — перечисление окон, фильтры (cloaked/`WS_EX_TOOLWINDOW`/
  панель задач/`Progman`/`WorkerW`), виртуальные ректы как источник истины,
  `DeferWindowPos`-батчи, WinEvent-хуки (новые окна встают в текущую камеру,
  ручные перемещения синхронизируются обратно), readback фактической
  геометрии (мин-размеры окон учитываются сами собой).
* `Snap` — примагничивание краёв с гистерезисом, кластеры как связные
  компоненты соприкасающихся окон.
* `Input` — `WH_MOUSE_LL` (колбэк минимальный: только PostMessage; тяжёлое —
  в главном потоке) + `RegisterHotKey`.
* `PreviewManager` — WGC: free-threaded frame pool, копия кадра под D2D-локом,
  корректное освобождение сессий, обработка закрытия окна во время захвата.
* `App` — кадровый цикл: `timeBeginPeriod(1)`, high-resolution waitable timer
  (`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`), тайминг на
  `QueryPerformanceCounter`; окна двигаются только когда камера реально
  изменилась; подложка перерисовывается только когда есть что менять.
